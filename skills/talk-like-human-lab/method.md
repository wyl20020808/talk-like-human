# 训练方法

路径约定：项目根目录是 /Users/apple/talk-like-human，下文的 evals/、notes/ 都在根目录；"写作 skill"指 skills/talk-like-human/。

**只在用户要求"学习""迭代""对比真人"时使用。** 平时回答问题不需要读这个文件。

核心：先按当前的 skill 写出自己的答案，再去看真人怎么答，逐题找差距，把反复出现的差距变成规则。

## 高质量模式（第二阶段，2026-10-28 起）

目标是人味足、质量也高（标准见写作 skill 的 genres/long-answer.md）。和下面的普通模式相比，有这些不同：
- **选题**：挑有专业深度、高赞质量高的题（知识、求助、分析类），每轮 3–5 题，宁少勿滥。还是只看标题。打开问题页时顺便确认标题没被合并改掉、回答能加载出来；前排都只有几十上百赞的题换掉（高质量第 1 轮：4 题里只有 1 题能好好对比）。
- **当成用户真的来问我**：用最专业的手段去解决。查一手资料（法规原文、论文、官方数据、原著），交叉核实，能算的自己算一遍，找出机制和常见误解。
- **v1**：按 skill 写好，在读任何回答前存档。
- **对比**：读前 2–3 个高赞，读全文（不只前 700 字），逐条对照 genres/long-answer.md 的五项，加上人味。先判断高赞本身质量高不高，营销腔、AI 腔、知乎腔不学。
- **反思**：每个差距要写清楚是"我不知道"（资料没查到）、"我没想到"（角度、机制）还是"我没写好"（结构、语气）。三种的改法不一样。
- **对照标杆**：写日常题、人际题时，v2 写完拿 写作 skill 的 examples/benchmark-zhihu-daily.md 对一遍，没它像人就继续改。
- **v2 要改语气，不只改事实**（2026-10-28：Claude 回答那一轮，v2 只补了事实，评论员腔原样留着，被用户指出）。改完整篇对照 写作 skill 的 examples/benchmark-zhihu-daily.md 和 core/anti-ai-tone.md 读一遍，专业题最容易退回去。
- **v2**：根据对比改写一版，再看一遍：比高赞好在哪、还差在哪。
- **沉淀**：反复出现的差距按 rule-management.md 写进对应文件，在 CHANGELOG 记一笔。

## 聊天样本模式（QQ、微信，2026-11-01 起）

- **来源**：用户在对话里粘贴、发截图，或给导出文件。只学用户自己愿意提供的群和对话。不解密聊天数据库，不进用户没提到的群，不在群里发消息。
- **脱敏**：原始聊天不进项目。昵称、群名、账号、手机号、地址、工作单位、私事都不记；evals/ 和 notes/ 里只留规律、统计，以及抹掉身份后改写的短片段。
- **先盲写**：把样本里的对话切开，只看到某一条为止，写自己的回复并存档，再看真人下一句。
- **记什么**：对话双方的关系、私聊还是群聊、单条长度、连发几条、多久没人接、怎么接话和换话题、表情和表情包、谁不回。
- **量化**：只把消息正文放进文本文件，一条一行，用 scripts/punct_stats.py 统计，"段末无标点%"就是不带句尾标点的消息比例。
- **沉淀**：通用的写进 genres/chat.md，QQ、微信各自的写进 platforms/qq.md、wechat.md。一个人的习惯不算规律；一个群的规律可以写成规则（用户 2026-11-01 定），要写明样本是什么群、多少条。

## 步骤（普通模式）

### 1. 选题（只看标题）
- 从平台的推荐页或热榜挑 10 个问题。**选题时只抓标题，不读回答和摘要**，免得被真人答案影响。
- 领域要分散：生活、情感、科技、文娱、脑洞、时事各来一些。
- 跳过敏感时政，跳过之前学过的题（查 notes/ 和 evals/self-iteration/）。

### 2a.（推荐）先查资料，认真想一遍
- 把每题当成真实用户的问题，用 WebSearch 查事实、数据、案例。**搜索时屏蔽目标平台**（比如 blocked_domains 填 zhihu.com），免得提前看到真人答案。
- 记下用到的来源和可信度；传言和未证实的说法单独标出来。
- 查完先判断题目的"玩法"（genres/README.md）。梗题和"有哪些"题，资料只是辅助，不是主体。
- 第 2 轮的教训：查资料能明显提升准确度和具体程度，但容易让回答变正经、变成文献综述。写的时候要把资料消化成故事和判断。

### 2. 先写自己的答案，并存档
- 按当前的 SKILL.md 和 references 写。不要为了"表现好"去刻意改变平时的写法，要的是真实水平。
- **读任何真人回答之前**，先把答案写进 `evals/self-iteration/YYYY-MM-DD-roundN.md` 的"第一步"一节。
- 不懂的题照实写不懂，这本身也是要对比的数据。

### 3. 读真人的回答
- 每题读排在前两位的回答（前 500–700 字），以及第一个回答下的 3–5 条评论。
- 抓取时把表情图片转成文字代码，并保留换行（参考 notes/ 里之前用过的抓取方法）。
- 只记规律和短片段，不记用户名和链接。
- **先判断真人答案本身是不是人话**（第 3 轮发现 10 题里至少 3 篇是 AI 辅助或营销腔）。高赞不等于该学，像 AI 的答案只能当反面例子。

### 4. 逐题对比
每题写三行："真人 1 / 真人 2 / 我的"，然后写"差别"。逐项对照下面这些方面：

| 方面 | 要问的问题 |
|---|---|
| 翻转 | 真人有没有把已知事实翻过来、算出一个意外结论？我只是在解释吗？ |
| 题目玩法 | 真人把它当求助题、梗题、"有哪些"题还是脑洞题？我当成了哪种？ |
| 审题 | 真人有没有指出题目的毛病、偷换的概念、错误的前提？我发现了吗？ |
| 资料怎么用 | 真人怎么用数据（藏进故事、一句带过）？我是不是在报论文？ |
| 人性立场 | 真人有没有站在"偷懒、舒服、开心"这一边？我是不是在说教？ |
| 切入点 | 真人从哪里下手：经历、故事、数字、圈内信息、反问？我从哪里下手？ |
| 具体程度 | 真人有几个具体的东西（人名、事件、数字、场景）？我有几个？ |
| 立场和情绪 | 真人站队了吗？有情绪吗？我是不是像分析师？ |
| 脑洞题 | 真人顺着假设玩了吗？我是不是在抬杠？ |
| 长度 | 真人在哪些题写长、哪些题写短？我是不是每题都差不多长？ |
| 口头禅 | 我这一批里有没有反复出现的句式？ |
| 事实 | 我有没有拿记忆冒充最新情况？ |
| 语气层 | 表情、换行、语气词、括号内心戏，参考 core/typing-texture.md |
| 评论区 | 评论在回应真人回答的哪一部分？对我的答案会怎么评论？ |

### 5. 给差别分类
- **可以学**：直接写进规则。
- **不能照搬**：比如亲身经历我没有。要找替代办法，比如用知识里的具体案例，或者用用户自己的情况，**不能编造**。
- **不该学**：知乎腔、营销腔、事实错误、人身攻击。写进黑名单，或者忽略。

### 6. 改规则
- **同一个差距至少在 2 题里出现，才改规则**，避免被个别题带偏。
- 改的时候写清楚：发现于哪一轮、哪些题，以及规则本身。
- 改完按 rule-management.md 检查行数和冲突。
- 在 notes/CHANGELOG.md 追加这一轮的记录。

### 7. 验证
- 每做 2–3 轮迭代，跑一次 evals/ 的盲评，确认规则改了以后效果确实变好，而不只是看起来规则更多了。
- 盲评结果存进 evals/results/。
