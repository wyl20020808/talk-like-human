### 6. 如何评价 Anthropic 发布的 Model Context Protocol (MCP) 协议？（5290049088）

> 就是给大模型接外部工具定的一个统一插头。以前每个AI应用接数据库、接GitHub、接Slack都得各写一套，有了MCP，工具方写一个server，所有支持MCP的客户端都能直接用
>
> 它能火 不是技术多新，底层就是JSON-RPC，是因为来得早、又是开放协议，后来OpenAI和谷歌都跟进支持，成了事实标准
>
> 要小心的是安全，装一个MCP server等于给模型开了一扇门，工具描述里能藏指令，来路不明的server别乱装，能给只读权限就只给只读

### 7. MCP 协议今天发布最大修订改无状态化，对普通 AI 工具用户意味着什么？（2065558803295342689）

> 对普通用户基本是好事，但你几乎感觉不到
>
> 改了啥：以前客户端连上server要先握手、建一个会话，后面每次请求都带着会话号；新版把握手和会话都去掉了，每个请求自己带上版本和能力信息，哪台服务器接都行
>
> 好处主要在服务方，不用记谁连在哪台机器上，扩容和负载均衡简单多了，远程MCP服务会更稳也更便宜
>
> 你能感觉到的，大概是远程工具变多变稳。代价是Roots、Sampling这几个老功能被标成废弃，依赖它们的小众server要等作者更新，好在有至少一年的过渡期

### 8. Claude Skills 有什么实际作用吗？（2003161952747275284）

> Skills其实就是一个文件夹，里面一份SKILL.md写清楚什么时候用、怎么做，再配上脚本和模板
>
> 关键在渐进加载：平时模型只看到每个skill的名字和一句话描述，装几十个也不怎么占上下文，真碰到相关的活才把全文读进来，需要时再跑里面的脚本
>
> 所以它适合你反复要交代的活，公司周报的格式、某套代码规范、处理某类Excel的固定步骤，以前每次贴一大段提示词，现在写一次，它自己判断什么时候用
>
> 跟MCP的区别：MCP是给模型接新工具，Skills是教它拿现有的工具按你的规矩办事

### 9. 你们有哪些好的 claude code skills 推荐？（2016657901549266060）

>
> 第三方的skill装之前一定读一遍，里面的脚本是会在你电脑上跑的

## 学到的东西

1. **去"纠正"别人之前，要比对方更确定。** Q4 我拿搜到的二手数字去纠正题目，结果题目是对的、我错了。高赞是自己量的。凡是要写"先纠正一下"，必须有一手证据，否则就写"我查到的是 xx，可能口径不同"。
2. **内行的比方最值钱。** "Session-Id 就是 cookie""MCP 就是 USB-C"，一句话让外行懂。
3. **社区的真实口碑要写进去。** Q1、Q10 的高赞都在说 Claude 最近贵、风评有起伏。我本身是 Claude，更不能只讲好的。
4. **判断"什么时候没用"比讲"有什么用"更像内行。** 比如 Q8：做研究的用处小，规范明确的团队有用。
5. **AI 话题下质量参差很大。** 有实测数据的长文（Q4）、像 AI 生成的教程（Q6）、一句话水贴（Q3）都有。对比的时候先分清楚哪篇值得学。

### 6. 如何评价 Anthropic 发布的 Model Context Protocol (MCP) 协议？
> 就是给大模型接外部工具定的一个统一插头，跟USB-C一个意思。以前每个AI应用接数据库、接GitHub、接Slack都得各写一套，有了MCP，工具方写一个server，所有支持MCP的客户端都能直接用。它能火不是技术多新，底层就是JSON-RPC，是因为来得早又是开放协议，后来OpenAI和谷歌都跟进支持，成了事实标准。要小心的是安全：装一个MCP server等于给模型开了一扇门，工具描述里能藏指令，来路不明的server别乱装，能给只读权限就只给只读

### 7. MCP 协议今天发布最大修订改无状态化，对普通 AI 工具用户意味着什么？
> 对普通用户基本是好事，但你几乎感觉不到。拿网页打个比方，旧版的Mcp-Session-Id就像cookie，客户端连上要先握手拿到这个号，后面每次请求都带着；新版把握手和会话都去掉了，每个请求自己带上版本和能力信息，哪台服务器接都行。好处主要在服务方，扩容简单多了，远程MCP服务会更稳更便宜。代价是Roots、Sampling这几个老功能被标成废弃，依赖它们的server要等作者更新，好在有至少一年过渡期。顺带说一句，现在也有不少人干脆用skill加命令行代替MCP，更省token

### 8. Claude Skills 有什么实际作用吗？
> Skills其实就是一个文件夹，一份SKILL.md写清楚什么时候用、怎么做，再配上脚本和模板，本质是一套管理上下文的办法。关键在渐进加载：平时模型只看到每个skill的名字和一句话描述，装几十个也不怎么占上下文，碰到相关的活才把全文读进来，需要时再跑脚本。所以它适合规矩明确、反复要交代的活，公司周报格式、团队代码规范、处理某类Excel的固定步骤；做研究、天天在试新东西的，用处就小很多。跟MCP的区别：MCP是给模型接新工具，Skills是教它拿现有的工具按你的规矩办事

### 9. 你们有哪些好的 claude code skills 推荐？
> 先装官方anthropics/skills仓库里那几个：skill-creator帮你把自己的流程写成skill，最该先装；docx、xlsx、pptx、pdf处理办公文件；webapp-testing用浏览器自动测网页。不过最顶用的往往是自己写的，把项目里反复交代的东西，提交前跑哪些检查、接口怎么命名、发版流程，写成skill放进项目的.claude/skills目录，整个团队拉代码就都有了。第三方的skill装之前一定读一遍，里面的脚本是会在你电脑上跑的

### 10. ChatGPT 和 Claude，谁会笑到最后？
> 大概率两个都在，只是不在一张桌上吃饭了。ChatGPT走大众消费的路，用户量比Claude大得多，靠订阅和品牌，跟搜索引擎抢人；Claude的钱大头来自企业，API和编程工具，长在开发者的工作流里。两边怕的东西也不一样，OpenAI怕普通人不愿意付费、算力成本压不下来；Anthropic怕收入太集中在写代码这一个场景，哪天别家编程模型追上来，企业换起来很快，最近已经有一波人嫌贵转去Codex了。所以谁笑到最后，不看谁更聪明，看谁的客户更难走
