### 1. 如何看待 claude 在国内封号如此严重，依然有大量死忠不停充？（1.3 万赞，回答是一长串段子："小写 ok 被定位到河北衡水""冷米饭要加热"……）

### 2. Anthropic 新规禁止持续虐待 Claude，这意味着什么？（7226 赞，回答两句话："Claude 很有恐怖游戏的感觉，富豪家的大小姐，养着是为了当邪神降临的容器"）

### 4. 为什么 claude code 都不让用了，好多人还是不放弃？（519 赞，回答：推荐 openclaude，"拿被动开源的 claudecode 改的"，配 DeepSeek，"无需翻墙"）

### 5. 为什么 Claude 的逻辑推理能力远超其他大模型？（229 赞，回答："扯淡了"，GPT 形式推理更强；Claude 强在面对的环境更"脏"，"任务的真实脏度"是衡量高级 AI 的标准）
> 任务脏度这个角度挺好 补一句能拿来量化的东西：形式推理看数学竞赛题，"脏任务"可以看SWE-bench Verified这种从真实GitHub issue里抽出来的题，或者Terminal-Bench这种让模型在终端里自己装依赖 跑命令 排错的测试。Claude这几代分数拉开差距主要就在这类上，纯数学竞赛反而没那么突出，正好对上你说的。不过benchmark也会被针对性优化，最后还是得看在自己的代码库里跑起来怎么样

### 6. Anthropic 凭 Claude Code 收入翻倍，该模型有何突出之处？（165 赞，回答：Claude Code 不是模型是 Agent 框架；官方文档的成本估算从每天 6 美元改成企业部署每天约 13 美元）
> 题目确实问歪了 Claude Code是壳 模型是Sonnet和Opus。补充几个压成本的点 比文档里那个平均数有用：一是上下文 别一个对话聊一整天，任务换了就/clear，长了用/compact压一下，token大头都耗在反复带着的上下文上。二是模型分工 计划和难的架构问题用Opus，日常改代码用Sonnet，/model里可以切。三是重复读的大文件和系统提示走缓存 缓存读取比正常输入便宜一个数量级。这几样做到 账单差别很大

### 7. 有没有可能 2026 年 Anthropic 还在用 MHA+Dense MLP 的模型架构？（160 赞，回答：引马斯克说 Sonnet 1T、Opus 5T；猜 Opus 4.5 转向了 MoE，因为价格从 15/75 降到 5/25；1M 上下文不太可能是纯 MHA）
> 推理链挺清楚 但有两个前提我会打个问号。马斯克的说法没有任何官方出处 拿来当基准不太稳。另外用价格倒推架构要小心，API定价里除了算力还有毛利、批处理折扣、缓存命中率、硬件代际，Opus降价同期也换了更新的推理硬件，不一定全是MoE带来的。1M上下文那条同意，纯MHA的KV cache扛不住，但具体是GQA、稀疏注意力还是别的压缩，外面确实没人知道

### 8. Anthropic 推出新模型 Claude Haiku，轻量模型降价提速对行业有何影响？（63 赞，回答：Haiku 5.5 便宜，适合当子 Agent；"prompt 小于 100k 的价格是高于 100k 的五分之一，50 万字的书分五次放入，总价只有一次性放入的五分之一"）
> 子Agent那个用法很对 不过分五次放入那段我有点没看明白，就算分段计价真是这样，把一本书拆成五段分开问，模型每次只看到五分之一，跨章节的问题就答不了了，省的钱是拿效果换的。真想省钱更该看的是缓存：同一本书反复问 第一次写进缓存 后面读缓存的价格只有正常输入的十分之一左右，再加上不急的活走Batch API还能打五折。这两样叠起来比拆书靠谱多了

### 9. 如何看待 Anthropic 提交 IPO 申请，将以「ANT」为代码登陆纳斯达克？（79 赞，回答：分析 S-1，五类股票，创始人的 Class F 和长期利益信托的 Class T 控制公司）
> 这个拆得很清楚 补个背景方便理解为啥这么设计：Anthropic本身是公益公司（PBC），法律上允许董事会在股东回报之外考虑公司使命，长期利益信托（LTBT）是2023年就设好的，信托成员跟公司没有经济利益关系。所以这次上市更像把原来那套结构原样搬进公开市场。对买股票的人来说 意味着你买的是分红权不是话语权，公司要是为了安全推迟发模型 股东基本拦不住，这个风险得自己掂量

### 10. 如何顺畅的使用 Claude Code？（回答：三种模式 Shift+Tab 切换，先用 Plan 模式规划，计划写进 md 文档，ctrl+g 可以编辑）
> 写得挺细的 补几个日常很顶用的：一是项目根目录放个CLAUDE.md 写清楚技术栈 跑测试的命令 代码规范，每次启动都会自动读，不用回回重复交代，第一次可以用/init让它自己生成个初稿。二是改坏了别慌 连按两下Esc可以回到之前的某一步重来。三是对话长了用/compact压缩上下文 换任务就/clear，不然越聊越慢还越贵。四是常用的提示词可以做成自定义命令 一个斜杠就调出来

学到的：
1. **先接住评论区的气氛，再说正经的。** 一句梗或者一句认同开头，后面接干货。Q2、Q3、Q7、Q9 的开头都按这个改了。
2. **评论区里有内行时，要比他们深一层。** Q4 初版只说"改 ANTHROPIC_BASE_URL"，评论区早就知道了；最终版改成回应"想要开源可控的客户端"，推荐有正经许可证的 opencode、aider。
3. **把传言和事实分开，就是专业评论的价值。** Q3 的 10T、Q7 的马斯克参数，都明说"没有可靠出处"。
4. **不和已有评论撞车。** Q10 已经有人补了"让 agent 跑测试"，我没再写这条。
5. **长度：** 用户要 200 字左右，最终 10 条都在 165–213 字。这在知乎评论区算长评，所以每条只围绕一个点展开，不列一堆。
