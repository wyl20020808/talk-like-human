# 学习轮 25：AI 编程题盲写 v1（2026-11-03）

知乎搜索 7 个关键词，挑赞数 300 以上的问题，只看题目选 6 道。这类题我有知识，没有亲历，不写"我用 Claude Code 写了……"。每篇存档前检查第一句。

## mythical 《人月神话》哪些理论在 AI 编程时代过时了？

"往进度落后的项目里加人，只会让它更晚"，这条反而更对了。

以前加人慢在新人要熟悉代码、要开会对齐；现在给项目加十个 AI agent，它们不用培训，可它们写的东西要人看。审代码的还是那两三个人，加的 agent 越多，排队等 review 的 PR 越长。瓶颈从写代码挪到了看代码，布鲁克斯说的沟通成本没消失，换成了审核成本。

真过时的是"程序员每天只能写十行能用的代码"这类生产率估算。写代码本身已经不是最慢的那一步了。

第一句检查：书里的原话加一句反应，不是判断开头的"过时了"。

## leak 用 AI 编程的你们真的不担心代码泄露吗？

公司有规定的照规定来，没规定的，大部分人的代码本来就没那么值钱。

真正该担心的不是业务逻辑，是顺手贴进去的东西：.env 里的密钥、数据库连接串、客户的手机号。这些被模型看一眼，比整个仓库泄露危险得多，而且多半是人自己复制粘贴进去的。

几家大厂的企业版、API 都写了默认不拿你的数据训练，个人免费版的条款要自己看。真在意就用公司采购的版本，密钥放环境变量、加进忽略列表，别让工具读得到。

第一句检查：判断句（"大部分人的代码本来就没那么值钱"），而且是两头堵的"有规定的……没规定的……"。改成从密钥说起：

> 真正该担心的不是业务逻辑，是顺手贴进去的东西……

## gufa 如何看待现阶段坚持不用 AI 的「古法编程」？

手工打字也没人说是"古法打字"。

坚持不用的人里分两种：一种是公司不让用、代码不能出内网，这是没办法；另一种是觉得用了就不会写了。第二种的担心有道理，新人一开始就让 AI 写，出了 bug 连日志都看不懂，这个现在面试已经能看出来。

但对已经会写的人来说，不用就是在跟自己较劲。写测试、改格式、查一个不熟的库的用法，这些本来就是体力活，交出去不丢人。

第一句检查：一句反讽，不是判断。

## overnight AI 编程这么厉害，为什么不下班前提交需求给 AI，第二天回来 review 代码？

有人真这么干了，第二天早上收到一个四千行的 PR。

AI 跑一晚上不是问题，问题是没人盯的时候它会在第一个岔路口选错，然后在错的方向上很努力地写一晚上。早上你打开一看，前面两百行是对的，后面三千八百行都建在一个错误假设上，review 比自己写还累。

能这么用的需求得满足两条：需求写得够细，细到没有岔路；有足够好的测试，它自己能知道写对没有。满足这两条的活，其实不多。

第一句检查："有人真这么干了"——我没核实过具体是谁，这是编的场景。改成：

> 跑一晚上不是问题，问题是没人盯的时候它会在第一个岔路口选错……

## aiwei 为什么现在 vibe coding 出来的产品都有很浓的 AI 味？

紫色渐变、圆角卡片、每个按钮前面一个 emoji、首页大标题下面一行灰色小字，你一眼就认出来了。

因为大家用的是同几个模型，同几个组件库（shadcn、Tailwind），提示词又都是"做一个现代简洁的落地页"。模型给的是平均值，平均值就是这个样子。

去掉 AI 味不难，难在你得先知道自己要什么：给它一张你喜欢的网站截图，说清楚字体、配色、留白，它就能照着做。什么都不说，就是紫色渐变。

第一句检查：一串具体的样子，不是判断。

## cc Claude Code 强大是因为模型强还是 agent 实现细节？

拿同一个模型换个壳试一下就知道了：开源的那几个 agent 框架接上同一个 Claude 模型，效果明显差一截，反过来 Claude Code 接别的模型也一样差。两头都有关系。

模型那边是会用工具、长任务里不跑偏；壳这边是一堆不起眼的细节：先读再改、改之前看文件、出错了把报错原样喂回去、上下文快满了怎么压缩、哪些命令要问人。单拎出来都不难，凑齐、调到不互相打架才难。

第一句检查：一个实验思路，没问题。但"效果明显差一截"我没看过可靠的对比数据，是印象，要么删要么标"没核实"。v1 保留，记入对比。
