做法：读完整题面、查资料写初版；再读每题前 3 个真人回答，对比后改出最终版。完整过程见 `2026-10-28-claude-answers.md`。

## 学到的东西

1. **去纠正别人之前，要比对方更确定。** 系统提示词那题，我拿搜到的二手数字（13.5 万字符）去"纠正"题目的 20 万，结果高赞是自己用 wc 量的，203 KB、两千来行。13.5 万应该是不算工具定义的版本。我把对的说成了错的，最终版已经改正。
2. **内行的比方最值钱。** "旧版的 Session-Id 就像 cookie""MCP 就是给模型用的 USB-C"，一句话就让外行懂了。
3. **社区的真实口碑要写进去。** 高赞里不少人说 Claude 最近贵、风评有起伏，有开发者转去 Codex。我自己就是 Claude，更不能只讲好的。所以我把"写代码领先基本没争议"改成了"长期在前面，但最近风评有起伏"。
4. **说清楚"什么时候没用"，比讲"有什么用"更像内行。** Skills 对规矩明确的团队有用，对天天试新东西的研究用处小。
5. **AI 话题下回答的质量差别很大。** 有自己实测数据的长文，有像 AI 生成的教程，也有一句话的水贴。对比之前先分清哪篇值得学。

## 第二次修改：AI 味（用户指出后重写）

2. **写成了评论员腔。** 插了很多点评："先别全信""写得很直白""真正值得盯的是""顺带说一句"；用了对称的句式："OpenAI 怕……，Anthropic 怕……"；还用金句收尾："不看谁更聪明，看谁的客户更难走"。

## 10 个回答（第二次修改后，又去掉了"最稳""最坑"这类词）

### 1. Anthropic 估值快破万亿了，Claude 已经比 ChatGPT 更好用了吗？
> 88.6对78这个分 换成人话就是十个真实项目里的bug 它比GPT多修好一个左右，你要是不写代码 这一个基本跟你没啥关系，平时问问题查东西ChatGPT照样好使 甚至更顺手。Claude Code是在终端里跑的 你让它改项目 它自己翻文件改代码跑测试，Anthropic这两年的钱大半就是程序员和公司按量刷出来的。不过最近风评也没那么香了 4.7 4.8被吐槽又贵又慢 有一拨人嫌账单跑去用Codex了，九千多亿的估值几乎全压在写代码这一个场景上 挺悬的

### 2. 对于物理系师生而言，ChatGPT、Gemini、Claude 的付费版在科研辅助方面谁更好用？
> 推公式三家都行 但都会在某一步偷偷把正负号弄反，你得一行行跟着看 别让它直接甩个最后结果。查文献就得防着点 三家都有联网深度研究 也都还会编出一篇不存在的论文，标题作者年份看着跟真的一模一样 每篇都得点开原文。写模拟程序 改LaTeX 理实验数据 交给Claude出错少一些，文件一多就上Claude Code 直接在代码目录里改 不用来回粘贴。也别指望用了agent做科研就轻松了 它省的是debug和调格式 脑子该怎么费还怎么费。只能买一个的话 天天写代码算数值的买Claude

### 3. 从大量处理文字的角度来看，Claude 和 ChatGPT 哪个更好用？
> 拿你自己的一篇长文档 两边各丢进去试一次，比看谁吹都准，重点看它记不记得住后半截的细节。改稿润色的话 Claude写出来少点那种整整齐齐的排比和金句，ChatGPT联网查资料 做表画图的工具多一些。要是几百上千份文件 千万别在网页里一份份贴，走API的批处理接口 价格打五折 丢进去挂着跑就行

### 4. Claude Opus 5 系统提示词泄漏，膨胀到 20 万字符的系统提示词，你怎么看？
> 有人直接拿wc量过 203KB 两千来行，20万没吹。但你真点开看 讲Claude是谁 该怎么说话的只占八分之一左右，剩下的全是各种工具的JSON定义 记忆系统怎么读怎么写 搜索和版权怎么处理，光工具定义就占了四分之一多。往前翻更有意思 Sonnet 3.5那会才两万多，基本是每多一个产品入口 就往里塞一段说明，跟模型聪不聪明关系不大。用API的不用管这个 API调用不带它 你写什么系统提示它就按什么来

### 5. 如何评价 9 月 23 日发布的 Claude Opus 5.5？
> 价格降到输入4刀 输出20刀一百万token 比Opus 5便宜两成，Terminal-Bench 4.0跑到66.4，官方还说同样的活token用得少 一个任务能省四成左右。这些分是Anthropic自己报的 第三方的还没出全。我倒是更在意省token那条，单价降两成谁都会降，一个任务要是真少烧一大截 天天挂着agent干活的团队月底账单是看得出来的。另外美国那边发布是22号 国内看到写23号的也没错

### 6. 如何评价 Anthropic 发布的 Model Context Protocol (MCP) 协议？
> 可以把它当成给大模型用的USB-C口。以前每个AI应用想接数据库 接GitHub 接Slack都得自己写一遍对接，现在工具那边写一个MCP server，支持MCP的客户端拿来就能用。技术上没啥新东西 底下就是JSON-RPC，能成是因为出得早还是开放的，后来OpenAI 谷歌都跟了 就成了事实标准。装的时候留个心眼 一个server就是给模型多开一扇门，工具描述里是能藏指令的，来路不明的别装 能只给读权限就只给读

### 7. MCP 协议今天发布最大修订改无状态化，对普通 AI 工具用户意味着什么？
> 拿网页打比方 旧版那个Mcp-Session-Id就是cookie，连上先握手领个号 之后每次请求都得带着，新版把握手和这个号都砍了 每个请求自己说清楚版本和能力 哪台机器接都行。你平时用AI工具 其实感觉不到啥变化，省事的主要是做服务的人 不用再记谁连在哪台机器上 扩容简单了，远程的MCP服务以后估计会多一些也稳一些。Roots Sampling这几个老功能标成了废弃 有一年过渡期，用到它们的server得等作者改。还有现在不少人干脆用skill加命令行 连MCP都不装了

### 8. Claude Skills 有什么实际作用吗？
> 一个文件夹 一份SKILL.md写着啥时候用 怎么做，再塞几个脚本和模板，就这么点东西。好用在它是按需读的，平时模型只看得见每个skill的名字和一句话简介，装几十个也不占多少上下文，用到了才把全文读进来。所以它适合那种规矩定死了 你又老得重复交代的活，周报格式 团队代码规范 某类表格固定怎么处理。你要是天天做实验试新东西 它帮不上啥。还有别跟MCP搞混 MCP是给模型接新工具，skill是教它拿现有的工具按你的规矩干活

### 9. 你们有哪些好的 claude code skills 推荐？
> 官方anthropics/skills里那几个先装上，skill-creator先装 它能帮你把自己的流程写成skill，docx xlsx pptx pdf处理办公文件，webapp-testing拿浏览器自己测网页。真正天天用的 一般是自己写的，你项目里每次都得叮嘱一遍的那些 提交前跑啥检查 接口怎么起名 发版走什么流程，写成skill丢进.claude/skills 整个组拉下代码就都能用。网上别人写的skill装之前一定打开看一眼 里面的脚本是在你电脑上直接跑的

### 10. ChatGPT 和 Claude，谁会笑到最后？
> ChatGPT的用户比Claude多太多了，吃的是普通人的订阅和牌子 对手更像是搜索引擎。Claude的钱大头是公司给的 API加编程工具 扎在程序员的工作流里。OpenAI头疼的是大家不太愿意掏钱 算力又贵，Anthropic的麻烦是收入太集中在写代码上，最近已经有一拨嫌贵的跑去Codex了，哪天别家编程模型再追上来 企业换起来可快了。照现在这样看 多半是俩都活着 各吃各的饭

## 事实和出处

- Opus 5.5：多数来源写美国时间 2026 年 9 月 22 日发布；API 输入 4 美元、输出 20 美元（每百万 token）；Terminal-Bench 4.0 是 66.4%；官方称单任务成本省约四成。来自引用官方的二手报道（VentureBeat、Artificial Analysis 等），属于厂商自报。
- Opus 5 系统提示词：203 KB、约两千行，工具定义约 27%、记忆系统约 23%，历代体积变化，均来自知乎高赞的实测（我没有独立复核）。泄露内容的真实性官方没有确认。
- MCP 2026-07-28 版本：去掉握手和 Mcp-Session-Id，Roots、Sampling 等标为废弃，至少保留 12 个月（Google Developers Blog、MCP 官方博客等）。
- 我比较有把握、这轮没逐条重查的：
  - MCP 基于 JSON-RPC，OpenAI、谷歌已支持。
  - Skills 的渐进加载机制。
  - anthropics/skills 仓库里的 skill-creator、docx、xlsx、pptx、pdf、webapp-testing。
  - Batch API 五折。
- 需要提醒的一点：这 10 个回答讲的都是我自己（Claude）和 Anthropic，发布的话最好注意这层关系。另外 Opus 5.5 那题是在评价我自己，里面只写了有出处的数字。
